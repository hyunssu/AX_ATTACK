01 · Database

DB 관계도

매뉴얼 시스템 핵심 테이블 구조. 레거시 _kyj 테이블은 별도 운영되며 이 관계도에서 제외.

핵심 RAG 청크 업로드·잡 분류 메타

manuals
매뉴얼 메타 정보. 카드 한 장 = 한 row.
예시
title"여신심사 매뉴얼"
categories["여신"]
sub_category"심사"
created_by"admin"
manual_versions
매뉴얼 버전별 파일 + 인덱싱 상태. index_step이 "done"인 최신 버전이 RAG에 서빙됨.
예시
version_no3
source_type"pdf"
index_step"done"
content_jsonnull (파일 업로드시) / BlockNote JSON (에디터시)
manual_parent_chunks
LLM 컨텍스트용 대형 청크 (~1500자). 검색 결과를 LLM에 넘길 때 이 텍스트를 사용.
예시
section_title"2. 심사 기준"
keywords["LTV", "DSR", "담보"]
content"2. 심사 기준\n주택담보대출 심사 시 LTV는..." (1500자)
manual_child_chunks
벡터·키워드 검색용 소형 청크 (~300자). embedding + tsvector 인덱스 보유. 검색 히트 → 부모 청크로 확장해서 LLM에 전달.
예시
content"주택담보대출 LTV 기준은 수도권 70%..." (300자)
embeddingvector(1536) — OpenAI text-embedding-3-small
manual_trails
카테고리별 소분류(trail) 목록. 사용자가 UI에서 직접 추가·수정. LLM 분류 프롬프트에 동적으로 주입됨(name 기준). 빈 trail도 허용. name_en으로 영문 UI 지원.
예시
category"여신"
name"심사"
name_en"Screening"
created_by"admin"
manual_categories
대분류 마스터 테이블. 기존 하드코딩(여신·수신·외환 등 7개)을 DB로 이관. color·color_light로 UI 색상까지 관리. /api/manuals/categories로 실시간 조회해 프론트에서 동적으로 렌더링.
예시
name"여신"
name_en"Credit"
color"#4a7fcb"
sort_order1
02 · Architecture

개발 방향

버전 인덱싱 라이프사이클

draft → converting → chunking → embedding → done
🏷️
DB 기반 동적 대분류
여신·수신·외환 등 대분류(category)를 코드 하드코딩에서 manual_categories 테이블로 이관. 색상·정렬 순서까지 DB로 관리하며, 프론트는 GET /categories를 마운트 시 호출해 동적으로 렌더링. Pydantic Literal 제약도 list[str]으로 완화.
manual_categories (name UNIQUE, color, color_light, sort_order)
🗂️
DB 기반 소분류 관리
소분류(subs)를 코드 하드코딩 대신 manual_trails 테이블로 관리. 사용자가 화면에서 직접 추가·수정하며, LLM 분류 시 DB에서 실시간 조회해 프롬프트에 주입한다.
manual_trails (category, name) ← UNIQUE
🔍
부모-자식 청크 RAG
검색 정밀도와 LLM 컨텍스트 품질을 분리. Child(~300자)로 벡터·키워드 검색 후, 매칭된 Parent(~1500자)를 LLM 컨텍스트로 전달.
child → embedding(vector) + content_tsv(FTS)
parent → section_title + keywords + content
📝
이중 상태 표시
매뉴얼마다 "서비스 중 버전"과 "현재 편집 상태"를 동시에 표시. 서비스 중인 RAG 버전은 유지하면서 초안 편집이 가능하다.
latest_done_version_no → RAG 서빙 중
latest_draft_index_step → 현재 편집 상태
🤖
LLM 호출 표준화
모든 LLM 체인 호출을 call_llm(chain, input, label=) 단일 래퍼로 통일. 재시도(최대 3회, exponential backoff)와 소요 시간 로깅을 공통 처리한다.
llm_clients.call_llm() ← tenacity retry
label → logging.getLogger("llm")
🌐
다국어 지원
매뉴얼별 lang_c(ko/en)로 언어를 관리. RAG 검색·응답 프롬프트가 사용자 언어에 맞게 동적으로 포맷된다.
manuals.lang_c CHAR(2) CHECK (ko | en)
format_prompt("key", language=lang_c)
📦
지연 배포 (Draft 저장)
파일 업로드 시 deploy=false 선택 가능. MinIO에 파일을 저장(storage_path)해두고 인덱싱은 나중에 수동 배포. 에디터에서 작성한 내용은 content_json(BlockNote JSONB)으로 초안 보관.
storage_path → 지연 인덱싱용 MinIO 객체명
content_json → BlockNote JSONB 에디터 내용
03 · API Reference

API 명세서

모든 엔드포인트는 JWT Bearer 인증 필요. prefix: /api/manuals

📄 파일 분석 & 섹션 등록
Method Endpoint 설명
POST /analyze
파일(PDF·md) 업로드 → 섹션 분리 → LLM으로 대분류·소분류 자동 분류. manual_trails에서 현재 소분류 목록을 실시간 조회해 프롬프트에 주입.
Form: file, context_category? → { file_name, file_url, source_type, sections[] }
POST /preview-sections
LLM 없이 파일에서 섹션만 분리해 미리보기. 분류 없이 구조만 확인할 때 사용.
Form: file → { sections[], section_count, source_type }
POST /reclassify-section
검토 모달에서 "정밀 재분류" 요청 시 호출. strong_llm(GPT-4o 급) + 전체 텍스트로 재분류. DB 소분류 목록도 함께 주입.
Body: { title, content } → { categories, sub_category, needs_review }
POST /confirm
검토 완료 후 섹션을 매뉴얼로 확정 등록. deploy=true면 즉시 인덱싱 잡 생성, false면 content_json에 BlockNote 블록으로 저장해 초안 보관. 새 소분류는 manual_trails에 자동 추가.
Body: { file_name, file_url, source_type, sections[], lang_c, deploy } → { results[] }
📋 매뉴얼 CRUD
Method Endpoint 설명
GET /
매뉴얼 목록 조회. 각 매뉴얼마다 latest_done_version_no(서비스 중)와 latest_draft_index_step(편집 상태)를 함께 반환. admin은 전체, 일반 사용자는 자신이 생성한 것만.
→ { id, title, categories, sub_category, lang_c, latest_done_version_no, latest_draft_index_step, ... }[]
POST /
단일 파일로 매뉴얼 직접 생성. 섹션 분석 없이 파일 전체를 한 매뉴얼로 등록. deploy 파라미터로 즉시 배포 또는 초안 저장 선택.
Form: title, file, deploy?, lang_c? → { manual_id, version_id, job_id? }
POST /quick-create
파일 없이 빈 매뉴얼 생성 (에디터 작성용). 제목만으로 AI가 소분류를 추천하며, 기존 sub_category와 다를 때만 추천 배지로 표시.
Body: { title, categories, sub_category?, lang_c } → { manual_id, version_id, ai_suggested_sub? }
GET /{manual_id}/versions
특정 매뉴얼의 전체 버전 목록. index_step으로 각 버전의 현재 상태 확인 가능.
→ { id, version_no, file_name, index_step, created_at }[]
POST /{manual_id}/versions
기존 매뉴얼에 새 버전 추가. 파일을 MinIO에 저장하고 deploy 선택에 따라 즉시 인덱싱 또는 초안 저장.
Form: file, deploy? → { manual_id, version_id, version_no, job_id? }
DELETE /{manual_id}
매뉴얼 삭제. admin 또는 본인 생성 매뉴얼만 삭제 가능. ON DELETE CASCADE로 manual_versions·청크 데이터 일괄 삭제. Trello 카드 ✕ 버튼에 연결.
→ { ok: true } / 403 권한 없음 / 404 없음
🏷️ 대분류 (Categories)
Method Endpoint 설명
GET /categories
manual_categories 테이블에서 대분류 전체 목록 조회. sort_order 순 정렬. 테이블 없으면 하드코딩 fallback 반환. 프론트 마운트 시 호출해 TAXONOMY를 동적으로 구성.
→ { name, name_en, color, color_light, sort_order }[]
📂 소분류·트레일 관리
Method Endpoint 설명
GET /trails?category=
카테고리별 트레일(소분류) 목록 조회. manual_trails 테이블 기준. 생성일 순 정렬.
Query: category → { name, name_en }[]
POST /trails
새 트레일 생성. 동일 (category, name) 조합이 이미 있으면 무시(ON CONFLICT DO NOTHING).
Body: { category, name, name_en? } → { ok: true }
PATCH /trails
트레일 이름 변경. manual_trails와 해당 소분류를 가진 모든 manuals.sub_category를 트랜잭션으로 일괄 변경. 정규화 없이 CASCADE 방식으로 일관성 유지.
Body: { category, old_name, new_name, new_name_en? } → { ok: true }
DELETE /trails
트레일 삭제. 해당 소분류를 가진 manuals.sub_category를 NULL로 일괄 초기화. Trello 컬럼 헤더 ✕ 버튼에 연결.
Body: { category, name } → { ok: true }
PUT /{manual_id}/sub-category
매뉴얼의 소분류를 변경하고 AI 추천 배지 제거. Trello 카드에서 AI 추천 수락 시 호출.
Body: { sub_category } → { ok: true }
DELETE /{manual_id}/ai-suggested-sub
AI 추천 배지만 제거 (거절). sub_category는 변경하지 않음.
→ { ok: true }
✏️ 에디터 (Draft)
Method Endpoint 설명
GET /{manual_id}/draft
에디터용 초안 조회. manual_versions.content_json(index_step=draft)에 저장된 BlockNote JSONB 반환. 없으면 manual_parent_chunks에서 마크다운으로 재조합해 반환(from_chunks: true).
→ { content: Block[], from_chunks: bool, raw_markdown? }
PUT /{manual_id}/draft
에디터 내용 저장. BlockNote 블록 배열을 JSONB로 upsert. 1500ms 디바운스 자동 저장 및 수동 저장 모두 이 엔드포인트 호출.
Body: { content: Block[] } → { ok: true }
POST /{manual_id}/deploy
초안을 운영에 배포. manual_versions.content_json을 새 버전으로 확정하고 인덱싱 잡 시작. 에디터 하단 "운영반영" 버튼에 연결.
→ { job_id, version_id }
⚙️ 인덱싱 잡 상태
Method Endpoint 설명
GET /jobs/{job_id}
인덱싱 잡의 현재 단계 조회. 프론트에서 2.5초 폴링으로 진행상황 추적. step=done 또는 error_message 존재 시 폴링 종료.
→ { step: "converting"|"chunking"|"embedding"|"done", error_message? }
